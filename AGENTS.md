# AGENTS.md

This is a StartOS service-package repository — it builds a `.s9pk` for StartOS.

Develop it inside a StartOS packaging workspace created by `start-cli s9pk init-workspace`,
which provides the packaging guide and agent context one level up. If you're reading this in a
bare clone with no workspace, the full guide is at <https://docs.start9.com/packaging>.

Work this package's `TODO.md` from top to bottom. Keep `README.md` (architecture, for developers and LLMs) and `instructions.md` (end-user docs) in sync with your changes.

## This repo

- **Package id is `metube`.** MeTube has no login of its own, so the web UI (interface id `ui`, port 8081) is gated by HTTP basic auth at the StartOS reverse proxy — username is always `admin`, the password is generated by the "Set Web UI Password" action and stored in `store.json`. A critical task (`init/watchPassword.ts`) blocks startup until the password is set, so the UI is never exposed unauthenticated.
- **File Browser is an optional dependency.** The "Select Download Destination" action can route downloads into File Browser's `data` volume (mounted read-write at `/mnt/filebrowser`) instead of MeTube's own `downloads` volume. MeTube runs as uid 1000 to match File Browser, so files it writes are immediately browsable there. The dependency only becomes required while File Browser is the selected destination.

## Inspecting a running install

To run a command inside the service's container (read its generated config, grep app logs), use `start-cli package attach metube -n metube-main -- <cmd>`. Select the subcontainer by **name** with `-n` (the name passed to `SubContainer.of` in `main.ts` — here `metube-main`) or by image with `-i`. Note: `-s/--subcontainer` matches the internal **Guid**, not the name, so passing a name to `-s` fails with "no matching subcontainers".
